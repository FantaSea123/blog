服务器漏洞之sql注入(1)

本篇整理自 PortSwigger Web Security Academy 的学习内容，覆盖 SQL 注入的原理、检测方法与两个经典示例（检索隐藏数据、破坏应用逻辑），附实操截图。

一、什么是 SQL 注入（SQLi）？

SQL 注入（SQLi）是一种 Web 安全漏洞，它允许攻击者干扰应用程序对其数据库发出的查询。这可以使攻击者查看到他们通常无法获取的数据，比如其他用户的数据，或者应用程序能够访问的任何其他数据。在许多情况下，攻击者还可以修改或删除这些数据，对应用程序的内容或行为造成持久性的改变。

在某些情况下，攻击者能够将 SQL 注入攻击升级，进而攻陷底层服务器或其他后端基础设施；它也可以被用来发起拒绝服务（DoS）攻击。

如何检测 SQL 注入漏洞

你可以对应用程序中的每一个输入点，系统地执行一组测试，从而手工检测 SQL 注入漏洞。为此，通常需要提交以下内容：

  • **单引号字符 '**，观察是否出现报错或其他异常。
  • 某些 SQL 特有语法：分别让该输入点求值为”原始（默认）值”和”另一个不同的值”，然后对比应用程序响应是否存在系统性差异。
  • 布尔条件，如 OR 1=1 和 OR 1=2，观察应用程序的响应是否有差异。
  • 能触发时间延迟的 Payload，让它在 SQL 查询中执行，观察响应时间是否变长。
  • OAST Payload：触发一条带外（OOB）网络交互，并监控是否真的产生了这样的交互。
