## 一、什么是 SQL 注入（SQLi）？

SQL 注入（SQLi）是一种 Web 安全漏洞，它允许攻击者干扰应用程序对其数据库发出的查询。这可以使攻击者查看到他们通常无法获取的数据，比如其他用户的数据，或者应用程序能够访问的任何其他数据。在许多情况下，攻击者还可以修改或删除这些数据，对应用程序的内容或行为造成持久性的改变。

在某些情况下，攻击者能够将 SQL 注入攻击升级，进而攻陷底层服务器或其他后端基础设施；它也可以被用来发起拒绝服务（DoS）攻击。

### 如何检测 SQL 注入漏洞

你可以对应用程序中的每一个输入点，系统地执行一组测试，从而**手工检测** SQL 注入漏洞。为此，通常需要提交以下内容：

* **单引号字符 `'`**，观察是否出现报错或其他异常。
* **某些 SQL 特有语法**：分别让该输入点求值为"原始（默认）值"和"另一个不同的值"，然后对比应用程序响应是否存在系统性差异。
* **布尔条件**，如 `OR 1=1` 和 `OR 1=2`，观察应用程序的响应是否有差异。
* **能触发时间延迟的 Payload**，让它在 SQL 查询中执行，观察响应时间是否变长。
* **OAST Payload**：触发一条**带外（OOB）网络交互**，并监控是否真的产生了这样的交互。

### 示例：检索隐藏数据

设想一个购物应用，它按不同类别展示商品。当用户点击 **Gifts（礼品）** 类别时，浏览器会请求这个 URL：

```
https://insecure-website.com/products?category=Gifts
```

这会使应用程序向数据库发起一条 SQL 查询，以获取相关商品的详情：

```sql
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```

这条 SQL 查询要求数据库返回：

* 所有列的详情（`*`）
* 来自 `products` 表
* 条件一：类别是 Gifts
* 条件二：`released = 1`

限制条件 `released = 1` 被用来隐藏尚未发布的商品。我们可以假定：对于未发布的商品，`released = 0`。

由于该应用程序没有针对 SQL 注入攻击实现任何防御，攻击者可以构造如下攻击，例如：

```
https://insecure-website.com/products?category=Gifts'--
```

这会生成如下 SQL 查询：

```sql
SELECT * FROM products WHERE category = 'Gifts'--' AND released = 1
```

关键在于，`--` 在 SQL 中是**注释指示符**，这意味着查询的其余部分会被当作注释，实际上等于被删除了。在本例中，查询不再包含 `AND released = 1`，因此**所有商品都会被展示出来，包括尚未发布的**。

你还可以用类似的攻击，让应用展示**任意类别**的所有商品——包括攻击者并不知道的类别：

```
https://insecure-website.com/products?category=Gifts'+OR+1=1--
```

这会生成如下 SQL 查询：

```sql
SELECT * FROM products WHERE category = 'Gifts' OR 1=1--' AND released = 1
```

这条修改后的查询会返回所有满足"类别是 Gifts **或** 1=1"的商品。由于 1=1 永远为真，查询会返回**所有商品**。

## 二、破坏应用逻辑（Subverting application logic）

设想一个允许用户用用户名和密码登录的应用。当用户提交用户名 `wiener`、密码 `bluecheese` 时，应用程序通过执行以下 SQL 查询来校验凭据：

```sql
SELECT * FROM users WHERE username = 'wiener' AND password = 'bluecheese'
```

如果查询返回了某个用户的详细信息，则登录成功；否则，登录被拒绝。

在这种情况下，攻击者**无需密码**就能以任意用户身份登录。他们可以利用 SQL 注释序列 `--`，把 WHERE 子句中的密码校验部分直接移除。例如，提交用户名 `administrator'--`、密码留空，最终生成的查询是：

```sql
SELECT * FROM users WHERE username = 'administrator'--' AND password = ''
```

这条查询会返回用户名为 `administrator` 的那个用户，并成功让攻击者以该用户身份登录。
